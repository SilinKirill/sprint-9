# Задание 3. Снижение нагрузки на базу данных

Сформированные отчёты сохраняются в MinIO и выдаются через кеширующий Nginx. Повторное скачивание использует готовый файл и не требует повторного чтения строк отчёта из ClickHouse.

## 1. Хранение отчётов в S3

В существующий [reports-api](../Task2/reports-api/) добавлен [ReportStorage](../Task2/reports-api/src/main/java/com/bionicpro/reports/storage/ReportStorage.java), работающий с MinIO через AWS S3 SDK. Отчёты сохраняются как JSON в приватном бакете `reports`. Для API создан отдельный пользователь с правами чтения и записи отчётов.

MinIO и постоянный том данных описаны в [docker-compose.yaml](docker-compose.yaml). Создание бакета и настройка прав доступа находятся в [minio/](minio/). Используются готовые архивные образы `bitnamilegacy/minio` и `bitnamilegacy/minio-client` с фиксированными версиями; они больше не обновляются.

## 2. Повторное использование отчётов и CDN

[ReportController](../Task2/reports-api/src/main/java/com/bionicpro/reports/controller/ReportController.java) проверяет готовность выбранного периода и наличие отчёта в S3. Если файл существует, API возвращает ссылку на него. Если отсутствует — читает подготовленные данные ClickHouse, сохраняет JSON в MinIO и возвращает ссылку. Ответ `GET /reports` содержит `{from, to, url}`.

Интерфейс скачивает файл по полученной ссылке через BFF и внутренний Nginx, который эмулирует CDN. В [nginx/nginx.conf](nginx/nginx.conf) настроены reverse proxy к MinIO, кеширование файлов на 24 часа и ограничение кеша 1 ГБ. Заголовок `X-Report-Cache` показывает `MISS` при загрузке из MinIO и `HIT` при выдаче из кеша.

Перед каждым скачиванием BFF проверяет сессию, а API — владельца и готовность всех суток периода. Это действует и при попадании в кеш. MinIO и CDN не публикуют порты; подписанная S3-ссылка остаётся между сервисами. Браузер получает `no-store`, файлы кешируются только во внутреннем Nginx.

## 3. Структура хранения и обновление кеша

Ключ объекта включает владельца, период и версию данных: `v1/<SHA-256(sub)>/<from>/<to>/<хеш версии>.json`. Пользователь определяется по проверенному JWT. В Task3 версия зависит от публикаций Airflow за выбранные сутки; с подключённым Task4 она также учитывает изменения CRM в новой витрине.

После повторной обработки периода Airflow публикует новый `batch_id`. API формирует новую ссылку, и Nginx загружает актуальный файл. Старая ссылка возвращает `409`. Для проверки актуальности API продолжает читать метаданные публикаций ClickHouse, но повторно не читает строки уже сохранённого отчёта.

Неиспользуемые файлы удаляются из кеша через 24 часа. Старые объекты S3 остаются в хранилище, но получить их по прежним ссылкам через приложение нельзя.

## Запуск и проверка

Запуск всех сервисов описан в [корневом README](../README.md#запуск). Контейнер `setup` создаёт локальный `Task3/.env` с ключами доступа и сохраняет существующие значения. `minio-init` автоматически создаёт приватный бакет и настраивает права. Секреты исключены из Git. Данные подготавливаются по [инструкции Task2](../Task2/README.md#подготовка-данных).

- Приложение: [https://localhost:8443](https://localhost:8443).
- Airflow: [http://localhost:8081](http://localhost:8081).

### Проверка через UI

1. Войти с OTP и дважды скачать отчёт за подготовленный период. В инструментах разработчика открыть **Network → запрос файла → Headers**. Ссылка одинакова, повторное скачивание возвращает `X-Report-Cache: HIT`; первая загрузка ещё не закешированного файла — `MISS`.
2. Повторно обработать выбранные сутки в Airflow и дождаться успешного завершения. Скачать отчёт снова: новая ссылка и `MISS`, затем `HIT` при повторном скачивании. Старая ссылка возвращает `409`.
3. Открыть актуальную ссылку без входа — `401`, под другим пользователем — `404`. Неготовый период возвращает `409`, пользователь без собственных протезов — `404`.

Автоматическая проверка сохранения отчётов, повторного использования S3 и обновления кеша Nginx:

```sh
docker compose run --rm --build --no-deps reports-tests
```

## Основные файлы

- `docker-compose.yaml` — MinIO, CDN и подключение к сервисам Task1/Task2.
- `nginx/nginx.conf` — reverse proxy и кеш файлов отчётов.
- `minio/`, `../setup/` — приватный бакет, права доступа и локальные настройки.
- `../Task2/reports-api/` — работа с S3, ссылки и проверка версии отчёта.
- `../Task1/bionicpro-auth/`, `../Task1/frontend/` — защищённое скачивание через BFF и интерфейс.
